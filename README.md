# 하나은행 AI 서류 사전점검 · 프론트엔드 프로토타입

Figma의 **하나은행 프로토타입 수정** 화면을 바탕으로 만든 React + Vite 모바일 웹 프로토타입입니다. Pretendard Variable을 프로젝트에 포함하고, Figma에서 제공된 아이콘과 이미지를 로컬 에셋으로 사용합니다.

## VS Code에서 실행하기

Node.js **20.19 이상(20.x) 또는 22.12 이상**과 Git이 필요합니다. Node.js 설치 후에는 VS Code를 다시 실행해 주세요.

VS Code 터미널에서 아래 명령을 순서대로 실행합니다.

```powershell
git clone https://github.com/amy9420/KDA_UIUX.git
cd KDA_UIUX
npm install
npm run dev
```

터미널에 표시되는 주소(기본 `http://127.0.0.1:5173`)를 브라우저에서 엽니다. VS Code의 **File → Open Folder**에서 `KDA_UIUX` 폴더를 열면 코드를 수정할 수 있습니다.

이미 내려받았다면 해당 폴더를 연 뒤 `npm install`, `npm run dev`만 실행하세요. `package.json`이 보이는 폴더에서 실행해야 합니다. `C:\Users\KDA`에서 `package.json`을 찾을 수 없다는 오류가 뜬다면 아직 프로젝트 폴더로 이동하지 않은 것입니다.

## 체험 흐름

1. 서비스 소개 → 하이챗봇에서 기업 형태·자금 용도 선택 → 맞춤 준비 서류 확인
2. 서류 자동 조회 → 필수 동의 → 서류 불러오기
3. 임대차계약서 등록 → 최근 파일의 시연용 PDF 선택 또는 기기의 실제 파일 선택
4. 서류 점검 → 보완 상세 → 재촬영·파일 교체·재점검 또는 직원 확인 요청
5. 제출 확인 → 필수 동의 → 접수 완료 → 나의 신청 확인

상품별 서류 안내, 촬영 가이드, 챗봇 추천 질문, 원문 미리보기, 파일 삭제와 교체, 접수번호 복사도 사용할 수 있습니다. 상단 헤더와 챗봇 입력창을 유지하고 본문만 스크롤합니다. 화면은 모바일 너비에 맞추며 PC에서는 가운데 표시됩니다.

## 시연 범위

- **프론트엔드 시연입니다.** 은행, 홈택스, 외부 AI, 실제 상담원과 연결하지 않습니다. 자동 조회·OCR 점검·재점검·제출·챗봇 답변은 샘플 상태와 정해진 응답으로 동작합니다. 실제 대출 신청이나 서류 접수가 이루어지지 않습니다.
- 기기 파일은 브라우저 메모리에서 미리보기하며 서버에 업로드하지 않습니다. PDF 또는 PNG/JPG/WEBP, 20MB 이하를 지원합니다. 이 제한은 시연 앱의 설정이며 은행의 제출 규정이 아닙니다.
- 실제 PDF는 브라우저의 PDF 뷰어로 확인합니다. 카드의 페이지 그림과 보완 감지 위치는 샘플이며 실제 PDF 페이지 수나 문서를 분석하지 않습니다. 실제 이미지의 인식 결과도 계산하지 않습니다.
- 촬영 화면의 기본 문서는 샘플입니다. **기기 카메라 / 사진 선택**은 브라우저와 기기에서 지원하는 경우 실제 촬영 또는 사진 선택을 엽니다.
- 데이터와 접수 내역은 새로고침하면 초기화됩니다. 접수번호는 `DEMO-`로 시작하는 시연 번호입니다. 필요한 백엔드·저장·인증·실제 AI 점검은 별도 구현 대상입니다.
- 기업 형태와 자금 용도 선택은 UI 상태에 반영됩니다. 서류 목록은 시연용 4종으로 고정되어 있으며 실제 상품별 요구사항을 판정하지 않습니다.

## 개발·검증

```sh
npm test             # 제출 조건, 교체·삭제, 파일 검증
npm run build       # 배포용 dist 생성
npm run preview     # 빌드 결과 로컬 실행
npx playwright install chromium
npm run test:e2e    # 브라우저에서 두 제출 경로, 업로드, 반응형 확인
```

`npm run dev`를 종료하려면 터미널에서 `Ctrl+C`를 누르세요.

## 코드 위치

- `src/App.jsx`: 화면, 네비게이션, 사용자 동작
- `src/components.jsx`: 헤더, 버튼, 모달, 문서 미리보기
- `src/styles.css`: 색상, 글꼴, 간격, 반응형 레이아웃
- `src/lib/model.js`: 서류 상태, 제출 조건, 파일 검증
- `public/figma`: Figma에서 받은 로컬 이미지·아이콘
- `tests`: Playwright 사용자 흐름 검증

화면은 DOM 텍스트와 CSS로 구성해 수정할 수 있습니다. 은행 UI는 사용자 제공 디자인을 참고한 학습·시연 용도입니다.

## 화면 및 인터랙션 보완

- 챗봇에 진입하면 첫 안내 → 사용자 예시 메시지 → 맞춤 안내가 순서대로 등장합니다. 추천 질문은 대화창으로 전송되며 잠시 후 해당 질문의 샘플 답변이 표시됩니다.
- 입력창에 글을 입력하면 전송 버튼, 입력 내용이 없으면 음성 체험 버튼이 표시됩니다. **음성 체험은 실제 마이크 권한이나 음성 인식 API를 사용하지 않습니다.** 파형과 샘플 문장을 보여준 뒤 사용자가 전송할 수 있습니다.
- 첨부 화면과 자동 조회 화면의 취소·뒤로가기·닫기는 진입한 화면으로 돌아갑니다.
- 소개, 등록, 제출 확인, 접수 완료는 390×844 화면에서 주요 하단 요소까지 보이도록 간격을 조정했습니다. 더 작은 화면과 글꼴 확대 시에는 본문을 스크롤할 수 있습니다.
- 스크롤바는 기본적으로 숨기고 스크롤 중에만 옅은 회색 표시를 잠시 보여줍니다. 접수 완료 체크에는 확산 애니메이션이 있으며 동작 줄이기 설정을 지원합니다.

재점검 화면은 점검 전과 같은 카드 컴포넌트를 공유하며, 보완 0건은 중립색으로 표시합니다. 소개 화면에서 챗봇을 다시 시작하면 이전 대화가 지워지고 순차 등장부터 다시 재생됩니다. 첨부 취소로 복귀할 때는 진행하던 대화를 유지합니다.

최근 파일에 두 가지 시연용 샘플이 있습니다. `임대차계약서.pdf`는 계약기간이 흐린 원본으로 보완 필요 결과, `임대차계약서_보완.pdf`는 수정된 문서로 정상 확인 결과를 보여줍니다. 첫 선택과 교체 모두 선택한 샘플 메타데이터를 기준으로 점검합니다. 원본은 재점검만 눌러도 통과하지 않으며, 보완본으로 교체하거나 직원 확인을 요청해야 합니다. 실제 업로드 파일의 OCR은 실행하지 않고 보완 필요 예시로 안내합니다. 단순히 파일명에 보완을 붙인 실제 업로드를 자동으로 통과시키지 않습니다. 교체·삭제는 이전 점검 상태를 초기화하고, 결과 화면의 뒤로가기는 현재 파일이 남은 등록 화면으로 돌아갑니다.
